## Опис проєкту

Компанія надає в оренду конференц-зали для бізнесу.

API дозволяє:

- створювати та редагувати конференц-зали;
- видаляти зали;
- шукати доступні зали за часом та місткістю;
- задавати доступні для залу додаткові послуги;
- створювати бронювання;
- перевіряти конфлікти бронювань;
- розраховувати вартість оренди;
- отримувати бізнес-звіти та статистику.

---

## Основний функціонал

### Конференц-зали

Для залу зберігаються:

- назва;
- місткість;
- базова вартість оренди за годину;
- доступні додаткові послуги.

Видалення реалізовано як **soft delete**: запис залишається в базі даних, але позначається як видалений і не повертається у звичайних API-запитах.

### Бронювання

Бронювання містить:

- зал;
- час початку;
- час завершення;
- загальну вартість;
- вибрані додаткові послуги.

API не дозволяє створити два бронювання одного залу з часовим перетином.

### Додаткові послуги

У проєкті реалізовані:

- Проєктор — 500 грн;
- Wi-Fi — 300 грн;
- Звук — 700 грн.

## API Endpoints

### Rooms

GET `/api/Rooms`  
Отримати список усіх активних конференц-залів.

POST `/api/Rooms`  
Створити новий конференц-зал.

PUT `/api/Rooms/{id}`  
Оновити дані конференц-залу.

DELETE `/api/Rooms/{id}`  
Видалити конференц-зал.

GET `/api/Rooms/available`  
Знайти доступні зали за часовим інтервалом та необхідною місткістю.

### Bookings

POST `/api/Bookings`  
Створити бронювання конференц-залу.

### Reports

GET `/api/Reports/revenue`  
Отримати загальну виручку та кількість бронювань за вказаний період.

GET `/api/Reports/rooms`  
Отримати статистику бронювань та виручки за залами.

GET `/api/Reports/services`  
Отримати статистику використання та виручки за додатковими послугами.

Приклад створення залу
POST /api/Rooms
{
  "name": "Зал D",
  "capacity": 80,
  "hourlyRate": 3000,
  "serviceIds": [1, 3]
}
Приклад бронювання
POST /api/Bookings
{
  "roomId": 1,
  "startTime": "2026-09-15T10:00:00",
  "durationHours": 2,
  "serviceIds": [1, 3]
}

У відповідь API повертає інформацію про бронювання та його загальну вартість.

## Розрахунок вартості

Вартість оренди залежить від часу бронювання:

- 06:00–09:00 — знижка 10%.
- 09:00–18:00 — базова вартість.
- 12:00–14:00 — націнка 15%.
- 18:00–23:00 — знижка 20%.

Часовий інтервал бронювання розбивається на частини відповідно до меж тарифних зон.

Наприклад, бронювання з 11:30 до 12:30:

11:30–12:00 — базовий тариф.

12:00–12:30 — тариф із націнкою 15%.

До вартості оренди додається вартість вибраних додаткових послуг.

Звіти та аналітика

Для бізнесу реалізовано три типи звітів.

Загальна виручка
GET /api/Reports/revenue?from=2026-09-01T00:00:00&to=2026-09-30T23:59:59

Повертає:

кількість бронювань;
загальну виручку;
період звіту.
Статистика за залами
GET /api/Reports/rooms?from=2026-09-01T00:00:00&to=2026-09-30T23:59:59

Повертає:

ідентифікатор залу;
назву залу;
кількість бронювань;
сумарну виручку.
Статистика за послугами
GET /api/Reports/services?from=2026-09-01T00:00:00&to=2026-09-30T23:59:59

Повертає:

ідентифікатор послуги;
назву послуги;
кількість використань;
отриману виручку.
Обробка помилок

Для автоматичної валідації моделей використовуються Data Annotations та [ApiController].

Для бізнес-помилок API використовує відповідні HTTP-статуси:

Код	Значення
200	Операція успішна
201	Ресурс успішно створений
400	Некоректний запит або недоступна послуга
404	Ресурс не знайдений
409	Конфлікт бронювання

Для помилок застосовується ProblemDetails.

У production-режимі внутрішні stack trace не повертаються клієнту.

Безпека

У проєкті реалізовано базові заходи безпеки:

PostgreSQL credentials не зберігаються у репозиторії;
підключення до БД зберігається через ASP.NET Core User Secrets;
HTTPS використовується для API;
у production використовується ExceptionHandler;
у production увімкнено HSTS;
Swagger доступний у режимі Development;
внутрішні деталі винятків не повертаються клієнту в production.

PostgreSQL;
Visual Studio 2022 або інше середовище розробки з підтримкою .NET 8.

3. Створення бази даних

У PostgreSQL створіть базу:

conference_booking

У Visual Studio:

ПКМ по проекту

Додайте:

{

    "DefaultConnection": "Host=localhost;Port=5432;Database=conference_booking;Username=postgres;Password=YOUR_PASSWORD"
  }

Замість YOUR_PASSWORD використайте власний пароль PostgreSQL.

Відкрийте:

Технічні рішення
Розділення відповідальностей

Бізнес-логіка розподілена між окремими сервісами:

RoomService — робота із залами;
BookingService — створення бронювань;
BookingAvailabilityService — перевірка доступності та конфліктів;
PricingService — розрахунок вартості;
ReportService — формування звітів.

Контролери відповідають переважно за HTTP-рівень і передачу даних між API та сервісами.

DTO

Для API використовуються окремі DTO, а не безпосередня передача Entity-моделей.

Це дозволяє:

контролювати структуру API;
не віддавати зайві навігаційні властивості Entity Framework;
уникати циклічних посилань під час серіалізації;
незалежно змінювати внутрішню модель БД та API-контракти.
Soft Delete

Видалення залів реалізовано через поле IsDeleted, тому дані фізично не видаляються з бази.

Робота з часом

Час бронювання нормалізується до UTC перед роботою з PostgreSQL.

Для часових значень у PostgreSQL використовується:
timestamp with time zone
